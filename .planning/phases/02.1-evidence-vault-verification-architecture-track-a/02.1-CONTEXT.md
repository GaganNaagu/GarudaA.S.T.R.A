# Phase 2.1: Evidence Vault & Verification Architecture (Track A) - Context

**Gathered:** 2026-11-15  
**Status:** Ready for planning  

<domain>
## Phase Boundary

Phase 2.1 delivers the forensic data persistence, verification workflow, and visual Evidence Gallery UI for candidate sightings. It enables investigators to inspect candidate matches with full context (reference photo, detected crop, full CCTV capture frame), examine forensic quality and similarity metrics, and update sighting verification status (`Unreviewed` → `Confirmed` → `Rejected`) with audit trails.

</domain>

<decisions>
## Implementation Decisions

### 1. Evidence Data Modeling
- **D-01:** Dedicated `SightingEvidence` ORM model in `database/models/infrastructure.py` (or `evidence.py`).
- **D-02:** Foreign key relationships to `missing_persons.id`, `camera_feeds.id`, `detection_events.id`, and `video_footages.id`.
- **D-03:** Explicit columns for forensic auditing:
  - `crop_image_path` (String) — relative path to face crop image
  - `full_frame_path` (String) — relative path to full CCTV capture frame
  - `similarity_score` (Float) — biometric similarity score (0.0 to 1.0)
  - `quality_score` (Float) — Laplacian blur variance score (sharpness metric)
  - `model_version` (String) — identifier of models used (e.g. `yolov8n-face+facenet512`)
  - `verification_status` (String) — `Unreviewed` (default), `Confirmed`, `Rejected`
  - `reviewed_by_id` (ForeignKey to `users.id`, nullable)
  - `reviewed_at` (DateTime with timezone, nullable)
  - `review_notes` (Text, nullable)
  - `bounding_box` (JSON) — `[x1, y1, x2, y2]` coordinates within full frame

### 2. Evidence Gallery UI & Visual Layout
- **D-04:** Dedicated "Evidence Vault" tab in Missing Person case details view (`apps/web-dashboard/src/app/missing/`).
- **D-05:** Side-by-side comparison cards per sighting:
  - Reference Missing Person Portrait (left)
  - Detected Face Crop (center)
  - Full CCTV Frame with highlighted bounding box (right)
- **D-06:** Interactive Lightbox Modal: Clicking any card opens a full-screen zoomable view with forensic metadata, camera details, timestamps, and action buttons.

### 3. Verification Workflow & Audit Mechanics
- **D-07:** Three-state machine: `Unreviewed` (initial) → `Confirmed` or `Rejected`.
- **D-08:** Review Modal: Prompting the investigator for optional/mandatory notes when confirming or rejecting a sighting.
- **D-09:** Confirming a sighting automatically logs an entry to `ActivityLog` and sets an "Active Lead" badge on the missing person case.

### 4. File Storage & Image Serving
- **D-10:** File storage organized hierarchically under:
  `services/backend/uploads/evidence/{case_number}/{sighting_id}/` containing `crop.jpg` and `full_frame.jpg`.
- **D-11:** Served securely through the existing FastAPI `/uploads/` endpoint with proper Content-Type headers and caching.

### the agent's Discretion
- Database index optimization on `missing_person_id` and `verification_status`.
- Skeleton loading animations in the Evidence Gallery while images are fetching.
- Toast notifications on verification status update success/failure.

</decisions>
