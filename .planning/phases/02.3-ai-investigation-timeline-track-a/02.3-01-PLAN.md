  <name>Task 2: Implement timeline aggregation service and FastAPI endpoint</name>
  <files>services/backend/services/timeline_service.py, services/backend/api/v1/endpoints/timeline.py, services/backend/api/v1/router.py</files>

  <action>
    1. Create `services/backend/services/timeline_service.py`:
       - Helper `_resolve_missing_person(db: AsyncSession, case_id: str) -> Optional[MissingPerson]` supporting UUID or `case_number` lookup.
       - Helper `_normalize_dt(dt: datetime) -> datetime` ensuring all datetimes are timezone-aware UTC (`dt.replace(tzinfo=timezone.utc)` if naive) so sorting never raises `TypeError: can't compare offset-naive and offset-aware datetimes`.
       - `async def build_case_timeline(db: AsyncSession, case_id: str, category: Optional[str] = None, order: str = "asc") -> CaseTimelineResponse`:
         - Fetches `MissingPerson` (raises 404 HTTPException if not found).
         - Emits `CASE_CREATED` (from `person.created_at`) and `PHOTO_UPLOADED` (if `person.photo_path` exists).
         - Queries `DetectionEvent` (`person_id == person.id`) with `selectinload(DetectionEvent.camera_feed).selectinload(CameraFeed.location)` -> emits `SIGHTING_DETECTED` with camera name, GPS (`lat`/`lng`), confidence, and map/evidence link.
         - Queries `SightingEvidence` (`missing_person_id == person.id`) with `selectinload(SightingEvidence.reviewer)` -> emits `SIGHTING_DETECTED` (if no matching `DetectionEvent` already emitted for `detection_event_id`, or enriches with `crop_image_path` and `sighting_id`) and `EVIDENCE_VERIFIED` / `EVIDENCE_REJECTED` when `reviewed_at` is present.
         - Queries `Alert` (`missing_person_id == person.id`) with `selectinload(Alert.assignments).selectinload(Assignment.officer)` and `selectinload(Alert.assignments).selectinload(Assignment.dispatch_unit)` -> emits `ALERT_TRIGGERED`, `ALERT_ACKNOWLEDGED`, `CASE_RESOLVED` (if `resolved_at`), and `UNIT_DISPATCHED` for each `Assignment`.
         - Queries `ActivityLog` where `entity_id` matches `person.id`, any of the case's `sighting_ids`, or any of the case's `alert_ids`, with `selectinload(ActivityLog.user)` -> parses JSON `details` safely and emits `AUDIT_LOG` / `VIDEO_PROCESSED` / `EVIDENCE_VERIFIED` events (avoiding duplicate entries if identical to `SightingEvidence.reviewed_at`).
         - Filters by `category` if provided and not `"all"`.
         - Sorts by normalized `timestamp` (`reverse=(order == "desc")`).
    2. Create `services/backend/api/v1/endpoints/timeline.py`:
       - `GET /case/{case_id}` returning `CaseTimelineResponse` with query params `category: Optional[str] = None` and `order: str = Query("asc", pattern="^(asc|desc)$")`.
    3. Register `timeline.router` in `services/backend/api/v1/router.py` under `prefix="/timeline"`, `tags=["Investigation Timeline"]`.
  </action>
