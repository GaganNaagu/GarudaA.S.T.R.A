## 1. Existing Data Sources & Schema Mapping

All timeline events for a given `MissingPerson` (`case_id`, accepting either UUID or `case_number`) can be aggregated without any schema migrations by querying existing SQLAlchemy models:

1. **Case Creation & Lifecycle (`database/models/registry.py` → `MissingPerson`)**:
   - `MissingPerson.created_at` → `CASE_CREATED` event (`"Missing person dossier registered"`), showing `case_number`, `priority`, `last_seen_location`.
   - `MissingPerson.photo_path` (when present) → `PHOTO_UPLOADED` / reference photo metadata attached to case creation or `ActivityLog`.
2. **Sighting Detections (`database/models/ai_events.py` → `DetectionEvent`, `database/models/system.py` → `SightingEvidence`)**:
   - `DetectionEvent` where `person_id == person.id` (joined with `CameraFeed` and `Location` for camera name & GPS coordinates).
   - `SightingEvidence` where `missing_person_id == person.id` (links `detection_event_id`, `crop_image_path`, `full_frame_path`, `similarity_score`, `verification_status`, `reviewed_at`, `reviewer`).
   - Emits `SIGHTING_DETECTED` (at `DetectionEvent.timestamp` or `SightingEvidence.created_at`) and `EVIDENCE_VERIFIED` / `EVIDENCE_REJECTED` (when `reviewed_at` is set).
3. **Alerts & Resolution (`database/models/ai_events.py` → `Alert`)**:
   - `Alert` where `missing_person_id == person.id`:
     - `created_at` → `ALERT_TRIGGERED` (`severity`, `status`)
     - `acknowledged_at` (if non-null) → `ALERT_ACKNOWLEDGED`
     - `resolved_at` (if non-null) → `CASE_RESOLVED` / `ALERT_RESOLVED`
4. **Field Dispatch & Assignments (`database/models/operations.py` → `Assignment`)**:
   - `Assignment` joined via `Alert` (`Alert.missing_person_id == person.id`), eager-loading `officer` (`Officer.user`) and `dispatch_unit`.
   - `Assignment.created_at` → `UNIT_DISPATCHED` (`officer`, `dispatch_unit`, `status`).
5. **Immutable Audit Trail (`database/models/system.py` → `ActivityLog`)**:
   - `ActivityLog` entries linked to the case (`entity_id == person.id`), its `SightingEvidence` IDs (`entity_type == "SightingEvidence"` and `entity_id in sighting_ids`), or its `Alert` IDs (`entity_type == "Alert"` and `entity_id in alert_ids`).
   - Captures `EVIDENCE_VERIFICATION_UPDATED`, `SEARCH_EXECUTED`, `PHOTO_UPLOADED`, and operator actions with `user` attribution and JSON `details`.

## 2. Backend Architecture (`02.3-01`)

- **Service layer**: `services/backend/services/timeline_service.py` (`build_case_timeline(db, case_id, event_type=None)`)
  - Resolves `case_id` by UUID or `case_number` (consistent with `evidence.py`).
  - Queries `MissingPerson`, `DetectionEvent` (+ `CameraFeed`), `SightingEvidence` (+ `reviewer`), `Alert`, `Assignment` (+ `Officer`, `DispatchUnit`), and `ActivityLog` (+ `User`).
  - Deduplicates overlapping `ActivityLog` vs `SightingEvidence.reviewed_at` entries when both represent the exact same review action, or preserves distinct audit details.
  - Normalizes all timestamps to timezone-aware UTC `datetime` and sorts chronologically (ascending or descending via query param `order=asc|desc`, defaulting to `desc` or `asc` — supporting both, default `desc` newest-first for live ops with toggle for chronological `asc` reconstruction).
- **Schemas**: `services/backend/schemas/timeline.py` (`TimelineEvent`, `TimelineLink`, `CaseTimelineResponse`).
- **Router**: `services/backend/api/v1/endpoints/timeline.py` mounted at `/api/v1/timeline` in `services/backend/api/v1/router.py`.

## 3. Frontend & `ui-ux-pro-max` Alignment (`02.3-02`)

Per `AGENTS.md` and `ui-ux-pro-max` (`data-dense-dashboard` + `navigation` accessibility guidelines):
- **Dense, scannable vertical timeline** inside a new tab `"Investigation Timeline"` on `apps/web-dashboard/src/app/missing/[id]/page.tsx`.
- **Stage-specific semantic icons & high-contrast badges** (`CASE_CREATED`, `PHOTO_UPLOADED`, `VIDEO_PROCESSED`, `SIGHTING_DETECTED`, `EVIDENCE_VERIFIED`, `ALERT_TRIGGERED`, `UNIT_DISPATCHED`, `CASE_RESOLVED`).
- **Category filter pills** (`All`, `Detections`, `Verification`, `Dispatch`, `Audit`) + **Order toggle** (`Chronological` / `Newest First`).
- **Direct deep-links (`TIME-03`)**:
  - Sighting / Evidence events → `"Inspect in Evidence Vault"` button switching to `evidence` tab (and optionally highlighting/scrolling to the sighting) + thumbnail preview of `crop_image_path`.
  - Camera / GPS events → `"View on Patrol Map"` link to `/patrol?lat=...&lng=...`.
  - Alert / Dispatch events → `"Open Alert Record"` link to `/alerts`.
- **Keyboard accessibility**: Proper `role="tab"`, `aria-selected`, focus-visible rings on filter buttons and links, empty and loading states.
